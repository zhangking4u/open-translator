# 桌面端翻译软件调研与对比分析

本文档记录了市面上主流桌面翻译软件的功能特点、UI/UX 亮点与优缺点，以及 OpenTranslator 可吸收借鉴的功能点（按 P0/P1/P2 优先级），供桌面客户端产品化迭代参考。

## 1. 调研对象

| 产品 | 平台 | 定位 | 备注 |
|---|---|---|---|
| DeepL 桌面版 | Windows / macOS | 商业机翻，质量导向 | 全局快捷键、屏幕捕获、整文档翻译、术语表、写作润色 |
| Bob | macOS | 翻译 + OCR 工具 | 划词/截图/输入三模式、翻译多开、原图翻译、OCR 独立模块、插件系统 |
| Pot | Windows / macOS / Linux | 跨平台划词 + OCR | Tauri+Rust，多接口并行、插件系统、外部调用 HTTP API、Wayland |
| TTime | Windows / macOS | 输入/截图/划词/悬浮球 | 替换翻译、折叠翻译、明暗模式、众多内置源 |
| Screen Translator | Windows | 屏幕翻译工具 | 悬浮球、区域截图→OCR→翻译、多服务 LLM+传统 API、历史记录 |
| Immersive Translate | 浏览器扩展 | 双语网页/PDF/字幕 | 原文+译文并排、inpaint 去原文图片翻译、术语库、双语字幕 |

## 3. 各产品核心特点与可借鉴点

### DeepL
- **核心**：`Ctrl+C+C` 全局划词（双击触发，降低误触）；屏幕捕获工具抠取屏幕任意区域文字并自动填入源文本框翻译；整文档翻译保留排版（PDF/DOCX/PPTX）；Glossary 术语表；DeepL Write 写作润色；已保存/收藏翻译跨端同步。
- **可借鉴**：双击快捷键触发；截图捕获后直接填入源文本框并自动翻译；术语表 UI；历史里星标/收藏。

### Bob (macOS，最值得参考的国产桌面产品)
- **核心**：划词/截图/输入三模式；**翻译多开**（同时开启多家服务并列对比，最多 10-12 个）；历史+收藏夹；语音朗读（原文/译文）；OCR 独立模块（截图/静默/访达选图/离线/连续/二维码/智能分段）；**原图翻译**（截图后在原图位置直接叠译文）；**驼峰/蛇形拆分**（代码标识符友好）；PopClip/AppleScript/Raycast 集成；菜单栏图标 + 偏好设置按功能域拆分（翻译/OCR/插件）。
- **可借鉴**：翻译多开并列对比；静默 OCR 直接复制剪贴板；原图翻译 + 锁定截图位置；设置页按功能域拆分（OpenTranslator 当前设置页过于极简）。

### Pot (Tauri+Rust，技术栈最接近)
- **核心**：划词/输入/外部调用/剪贴板监听/截图 OCR/截图翻译；多接口并行翻译+多接口 OCR+多接口 TTS；导出生词本（Anki/欧路）；**插件系统**（自定义翻译/OCR/TTS/生词本接口）；全平台+Wayland；第一/第二目标语言；动态翻译（输入即实时翻译）。
- **可借鉴**：插件系统架构（OpenTranslator 已是 Rust，可设计扩展 engine/ocr/tts 的插件）；外部调用本地 HTTP API（供其他工具调用）；剪贴板监听翻译；动态/实时翻译开关。

### TTime
- **核心**：输入/截图/划词/悬浮球四模式；**替换翻译**（直接把选中文本换成译文）；**折叠翻译**（默认隐藏，点击展开，减少打扰）；明暗模式；众多内置翻译源。
- **可借鉴**：替换翻译（桌面端缺失，邮件/代码/文档中非常实用）；折叠/展开翻译气泡（避免频繁弹窗干扰）；悬浮球点击后再翻译（比自动触发更省资源，OpenTranslator ball 可参考）。

### Screen Translator (Windows)
- **核心**：悬浮球快速交互；区域截图→OCR→翻译；划词；多服务（LLM+传统 API）；历史记录窗口；默认快捷键 Ctrl+Alt+T/D/H。
- **可借鉴**：悬浮球与结果弹窗分离的交互流程；快捷键方案可参考。

### Immersive Translate (浏览器扩展，UX 参考)
- **核心**：网页双语对照（原文+译文并排）；PDF/EPUB/字幕翻译保留排版；YouTube/Netflix 双语字幕；图片/漫画翻译带 **inpaint 去原文背景再叠译文**（比单纯覆盖文本框好看）；术语库、领域设置、上下文翻译；鼠标悬停显示原文。
- **可借鉴**：OpenTranslator shot viewer 的“悬停显示原文”已有；可向 inpaint 级图片翻译演进；术语表可加领域/上下文设置。

## 4. OpenTranslator 桌面端现状与差距

现状：底座已具备（Tauri + Rust + llama.cpp 本地推理 + 划词/截图/实时字幕/托盘/全局快捷键），但：
- 交互入口单一：缺输入翻译、剪贴板监听、静默 OCR；
- 结果呈现单一：缺多 engine 对比、收藏历史、替换翻译（macOS 不支持）；
- 产品化细节不足：TTS、术语表 UI、设置页分层、菜单栏细化。

## 5. 建议吸收的功能（按优先级）

### P0（短期，补齐“产品感”最缺失的）

1. **输入翻译**：全局快捷键唤出一个小翻译输入框，手动输入/粘贴翻译，Enter 触发。桌面翻译最基本的“查词”入口，目前缺失。
2. **自动复制翻译结果**：可选开关，翻译完成后自动写入剪贴板，无需点复制按钮。
3. **静默 OCR / 截图 OCR**：截图后只把识别文字复制到剪贴板，不弹翻译窗口；或纯 OCR 窗口独立于翻译，让用户把软件当 OCR 工具用（Bob 有大量用户纯用 OCR）。
4. **历史记录收藏与 UI 升级**：现有 `history::HistoryEntry` 仅本地存储，且无收藏/星标、无搜索。在历史面板加星标收藏、搜索、重译、复制。
5. **替换翻译 macOS 支持与 UI 可见性完善**：`replace_text` 已有 Win/Linux 实现，macOS 缺；UI 上 replace 按钮仅在 `replaceable` 时显示，需与快捷键/菜单统一。

### P1（中期，差异化竞争力）

6. **翻译多开 / 多 engine 并列对比**：同一段文本同时用多个 engine 翻译并列展示（Bob 的杀手级功能）。
7. **原图翻译增强**：在 shot viewer 基础上支持“去原文+译文原位叠加”（类似 inpaint），让截图翻译看起来像本地化界面。
8. **TTS 完善**：Windows/macOS 原生语音合成，支持原文/译文朗读、语音选男/女、语速。
9. **术语表管理 UI**：glossary.txt 目前靠手动编辑文件，建议加图形化增删改 + 域名/领域作用域。
10. **驼峰/蛇形拆分**：选中 `getUserName` 这类标识符自动拆分再翻译（针对程序员场景）。

### P2（中长期，生态化）

11. **插件系统**：自定义翻译引擎/OCR 引擎/TTS/生词本导出接口。
12. **本地 HTTP 外部调用 API**：供其他桌面工具/快捷键软件调用翻译（Pot 的 `127.0.0.1:port/selection_translate` 模式）。
13. **查词/字典模式**：显示词形、释义、例句、发音，不只是机翻一句。
14. **离线模式推广**：强化 llama.cpp 本地模型的离线翻译体验（无网络也可用）。
15. **设置页重构**：拆分为 翻译/OCR/快捷键/外观/服务/关于，支持菜单栏图标（macOS）和托盘子菜单细化。

## 6. 建议路线图

- **近期（本版本）**：完成 P0 中的输入翻译、自动复制、静默 OCR、历史收藏、替换翻译 macOS 支持。
- **下一版本**：P1 中的翻译多开、原图翻译增强、TTS 完善、术语表 UI。
- **后续**：P2 中的插件系统、外部调用 API、查词模式、离线模式、设置页重构。
