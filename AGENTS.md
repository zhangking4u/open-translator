# AGENTS.md

OpenTranslator: local-first AI translation platform. Four Rust crates plus a browser extension exist: `core/translator-service` (HTTP service + engines), `core/inference` (llama.cpp actor engine), `desktop/translator-core` (platform-agnostic desktop lib), `desktop/translator-popup-tauri` (Tauri v2 client, shipped on Windows/macOS/Linux) and `browser/extension`. The legacy GTK/eframe clients were removed in v0.3.0 (still available in git history and older release tags). `tests/` is an empty placeholder; `README.md` is the user guide — `docs/` is the project context.

## Repo layout / build

- The core crate is `core/translator-service`. There is no root Cargo.toml or workspace: run all cargo commands from the crate directory:
  - `cargo run` — Axum server at `TRANSLATOR_BIND_ADDR` (default `http://127.0.0.1:17890`)
  - `cargo test` — unit tests plus `tests/api.rs` (tower `oneshot`) and `tests/ollama.rs` (local axum stub server) integration tests; no external services needed
  - `cargo check`
- `core/inference` (crate `translator-inference`) wraps llama.cpp via `llama-cpp-2` using an actor worker thread (safe Rust, requests serialized over a channel): `InferenceEngine::load(model_path, LoadOptions)` + `generate(prompt, stop_strings, GenerateOptions)` + `generate_streaming(..., on_delta)` which reports every decoded token piece to a callback. Building it needs cmake + clang/libclang (see the dev-machine bullet); the real-model test is gated by `TRANSLATOR_TEST_MODEL`. It backs the service's `llama-cpp` engine and the shipped Tauri desktop client's embedded inference (Windows/macOS/Linux).
- `desktop/translator-core` is a platform-agnostic lib (no GTK): CLI args/config precedence, HTTP translate client (`translate::translate`, plus `translate::translate_stream` which parses the SSE deltas from `POST /translate/stream`), service health checks and auto-start, per-OS paths (Linux XDG, Windows `%APPDATA%`/`%LOCALAPPDATA%`, macOS `~/Library`), the shared language list (`languages::LANGUAGES` / `languages::label` / `languages::source_options` with the `auto` entry), source-language detection (`detect::detect` using `whatlang` trigrams, `detect::resolve_source` replaces `auto` with a detected tag when confident and keeps `auto` otherwise), the model downloader (`models::download`: ModelScope URL + SHA-256, resume via HTTP Range, `download_client()` sets a User-Agent because ModelScope's CDN returns 403 without one; `reqwest` needs the `rustls-tls` feature for it), the recent-translation history (`history::HistoryEntry` with `push`/`load`/`save`, newest first, deduped by text + target, capped at 10, stored in `paths::history_path()` = `history.json` next to the config), and the startup update check (`update::check` against the GitHub `releases/latest` API, which also parses the release `assets` so the client can pick its update package; the release workflow embeds the tag via `OPEN_TRANSLATOR_VERSION`; `check_updates` / `TRANSLATOR_CHECK_UPDATES` toggles it). CI runs its tests on ubuntu, windows and macos. The shipped Tauri client depends on this crate by path.
- `desktop/translator-popup-tauri` is the shipped Tauri v2 client (Windows/macOS/Linux), built from its crate with plain cargo and a no-bundler HTML/CSS/JS frontend (`ui/`, `tauri.conf.json`, `capabilities/`, `icons/icon.ico`): `src/main.rs` embeds the llama.cpp engine — tray (显示窗口/历史…/设置…/有新版本/退出), global shortcut from config/`TRANSLATOR_HOTKEY`, `--autostart`/`--settings`/`--history`/`--translate`/`--stdin`/`--print`, single-instance forwarding of `--translate`/`--settings`/`--history`, card shortcuts (`Ctrl+H` history, `Ctrl+,` settings, `Ctrl+1/2/3` recent targets, `Ctrl+Shift+C` copy, `Ctrl+Enter` retranslate), cursor placement, pin, history (`translator-core::history`), settings (`settings::persist_value`), notifications (`src/notify.rs`), the extension HTTP API (`src/server.rs`) and one-click updates (Windows extracts the zip and runs `install.ps1`; Linux downloads the deb, verifies the GitHub asset SHA-256, stages it in a private 0700 directory and installs it with `pkexec apt-get`, then restarts itself; without pkexec/apt or a digest it falls back to the release page); `src/capture.rs` is shared selection capture — Linux reads `wl-paste --primary` with an X11 PRIMARY fallback for Xorg sessions and implements replace-in-place for managed X11/XWayland source windows (`x11rb` focus + `enigo` Ctrl+V; native Wayland sources cannot be replaced). The Linux client copies through `arboard` (X11 clipboard) and speaks through `speech-dispatcher` (`spd-say --wait`, stopped with `--stop`/`--cancel`, voice selected from the target language via `-l`, button hidden by `tts_voice_available` when no voice matches), because WebKitGTK exposes no `speechSynthesis`. On Linux it needs `libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev patchelf pkg-config` to build; CI builds it on ubuntu, windows and macos, and the deb ships it as `/usr/bin/translator-popup`; `packaging/linux/make-deb.sh` builds it from this crate (binary at `/usr/lib/open-translator/translator-popup` plus the `/usr/bin/translator-popup` symlink, desktop entry, icon; runtime deps `libwebkit2gtk-4.1-0`, `libgtk-3-0t64 | libgtk-3-0`, `libayatana-appindicator3-1`, `wl-clipboard`, `libnotify-bin`, `libgomp1` plus Recommends `speech-dispatcher`, `pkexec`; needs glibc ≥ 2.39 because it builds on Ubuntu 24.04), and `open-translator-setup` registers the GNOME shortcut as `<bin> --translate` and writes the `--autostart` entry under `~/.config/autostart` (`--uninstall` removes both). GNOME/Mutter does not implement the data-control protocol, so `wl-clipboard-rs` cannot be used. On Wayland sessions it prefers the X11 backend (`prefer_x11_backend` sets `GDK_BACKEND=x11` when `DISPLAY` is available and `GDK_BACKEND` is unset) because native Wayland has no keep-above and GNOME refuses focus/raise to a token-less background app; `show_main` also pulses always-on-top for 700 ms on every show so tray/hotkey commands bring the card to the front even when it was hidden and would otherwise map below a fullscreen window (`GDK_BACKEND=wayland` opts out — 固定 then only prevents hiding). On an autostart launch it also nudges the update menu item (4 s and 15 s after startup) because a session-start race in the AppIndicator extension can leave the menu labels empty and it only re-reads the properties when an update arrives while the menu is closed. `desktop/install-windows.ps1` builds it into a short `%LOCALAPPDATA%\OpenTranslator\build` target dir (MSBuild FileTracker hits a path-length limit when `llama-cpp-sys-2` builds under a deep repo path), stops a running instance first (Windows locks running executables) and installs a Startup `--autostart` shortcut to the Tauri binary (`-Uninstall` removes it, `-NoStart` skips the tray restart); `desktop/install-macos.sh` builds a `~/Applications/OpenTranslator.app` bundle (Tauri client) plus a LaunchAgent (`--uninstall` removes both); both warn when no model file is present.
- `browser/extension` holds shared extension sources (plain JS, no bundler): Firefox uses `manifest.json` (MV2, `data_collection_permissions.required = ["none"]`, `strict_min_version` 142), Chrome uses `manifest.chrome.json` (MV3, service worker, `host_permissions`); `browser/build.sh [firefox|chrome|all] [--zip]` copies them into loadable dirs/zips under `browser/dist/` (gitignored; zips contain a top-level folder plus the `packaging/browser/README.txt` install guide and ship as `OpenTranslator-browser-chrome.zip` / `OpenTranslator-browser-firefox.zip`) and `browser/sign.sh` signs the Firefox build via `npx web-ext sign --channel unlisted` (needs `WEB_EXT_API_KEY`/`WEB_EXT_API_SECRET`; the xpi download is the last step — do not interrupt; AMO rejects reused version numbers, so bump the manifest version before re-signing). The content script (all frames) shows a streaming bubble whose visible controls are state-driven (target-language selector, copy and a `⋯` menu with bilingual/original copy, TTS, replace-original, retranslate, language swap and a settings link; only 停止 while streaming, only 重试 on error), with replace-original in `<input>`/`<textarea>`/`contenteditable`, `<input>`/`<textarea>` selection support, auto-translate noise guards (`autoTranslateMinLength`/`autoTranslateDelay`) and a per-site opt-out (`disabledSites`, toggled from the popup); the toolbar popup (`popup.html`) reports `/health` status, recent history (`history`) and quick language/auto-translate/site toggles, with a background badge refreshed via `alarms`; the background streams `POST /translate/stream` over a long-lived port (cold-start retries) and falls back to `/translate`; the `translate-clipboard` command reads the clipboard in the content script, and context-menu clicks on pages without a content script (PDF viewer) open `result.html` with the selected text. Validate with `python3 -m json.tool *.json`, `node --check *.js` and `npx web-ext lint --source-dir browser/dist/firefox`; load via `about:debugging` (Firefox) or `chrome://extensions` (Chrome). Note: match patterns cannot contain ports, so the host permission is `http://127.0.0.1/*`. Headless smoke test without a GUI: `browser/test.sh` launches Chrome/Edge with `--headless=new --remote-debugging-port`, loads the MV3 build via CDP `Extensions.loadUnpacked` and drives the service worker plus the content-script isolated world (`--load-extension` is ignored by Chrome 137+; a mock service is started when none is running — building it on a dev machine needs cmake/clang, and the browser log is printed when the debug port does not open).
- `Cargo.lock` is committed per crate; keep them and run `cargo test --locked` when touching dependencies.
- CI lives in `.github/workflows/ci.yml`: `cargo test` for `core/translator-service`, `core/inference` and `desktop/translator-core` (matrix on ubuntu/windows/macos; a `windows-latest` job also runs the core tests to keep the service portable), a Tauri client job testing `desktop/translator-popup-tauri` on ubuntu/windows/macos (Linux installs webkit2gtk-4.1/gtk3/ayatana dev packages; the Windows runner exercises the update-pipeline test), a `tauri-frontend` job validating the `tauri.conf.json`/`capabilities` JSON and `node --check ui/main.js`, browser static checks + `web-ext lint`, and a Chrome e2e job running `browser/test.sh` (starts a mock-engine service if none is running). Core and desktop-client jobs build llama.cpp (cmake/clang are on the runners; cached after the first run). Releases: `.github/workflows/release.yml` (tag `v*` or manual `workflow_dispatch`) builds the Windows zip (`packaging/windows/install.ps1` + README + exe; the installer stops a running instance before replacing it), the macOS dmg (`packaging/macos/make-dmg.sh` + `Info.plist`, bundle includes the client only) the Linux deb (`packaging/linux/make-deb.sh`, Tauri client) and the browser extension zips (job `browser-extension`, `browser/build.sh all --zip`; Firefox is unsigned, so the zip only supports temporary loading) and attaches them to the GitHub release; build steps inject `OPEN_TRANSLATOR_VERSION` from the tag for the update check; use `workflow_dispatch` + `gh run download` to test packaging without tagging. License: MIT (`LICENSE`).
- A root `tests/` dir exists but is not a Cargo test dir — Rust tests belong under `core/translator-service/tests/` or as `#[cfg(test)]` modules. `models/` holds the HY-MT → Ollama import script (`import-hymt-ollama.sh`).
- Root `.gitignore` ignores Rust `target/`, `browser/dist/` and `packaging/linux/build/`; `.kilo/.gitignore` covers JS tooling files inside `.kilo/` only.
- Active branch is `main`.
- Dev-machine runtime (not repo state): Ollama v0.35.0 at `~/.local/opt/ollama` (models in `~/.ollama/models`; installed: `hy-mt1.5-1.8B` GGUFs in `/tmp/kilo/hymt` are ephemeral, `translategemma:4b`, `qwen2.5:7b`, `qwen2.5:3b`; start with `~/.local/opt/ollama/bin/ollama serve`). To build `llama-cpp-2` locally: cmake at `~/.local/opt/cmake` (user-space) and `clang`/`libclang-dev` from apt, with `PATH="$HOME/.local/opt/cmake/bin:$PATH" LIBCLANG_PATH=/usr/lib/llvm-21/lib`. Network quirk: `ollama.com` and HuggingFace are unreachable; ModelScope works and GitHub release assets need a proxy such as `https://gh-proxy.com/`.
- No CI workflows and no rustfmt/clippy config; verify locally with `cargo test`. Existing sources are not rustfmt-formatted, so don't run repo-wide `cargo fmt` unprompted.

## Architecture (current state)

`src/lib.rs` exposes `api`, `config`, `domain`, `engine`; `src/main.rs` is bootstrap only (`Config::from_env()` → `engine::build(&config)` → `api::router(...)` → bind).

Flow: `src/api/mod.rs` (router + handlers + DTOs + error mapping) → `src/domain/` (`translation.rs` types/errors, `language.rs` tag normalization, `prompt.rs` prompt styles) → `src/engine/mod.rs` (`TranslationEngine` trait, `EngineKind`, `build` factory) → `src/engine/mock.rs` / `src/engine/ollama.rs` / `src/engine/timeout.rs` (`MockEngine`, `OllamaEngine`, `TimeoutEngine` wrapper).

- `TranslationEngine::translate` is async and dyn-compatible: it returns `TranslationFuture` (`Pin<Box<dyn Future<Output = Result<TranslationResult, TranslationError>> + Send + '_>>`), and the trait has `Send + Sync` supertraits so API state is `EngineRef` (`Arc<dyn TranslationEngine>`). New engines must use this signature — plain `async fn` in the trait would break `dyn` support.
- `TranslationEngine::translate_streaming` reports decoded pieces through a `DeltaCallback` (`Box<dyn FnMut(&str) + Send + 'static>`); the default implementation emits the complete translation as one delta, `LlamaCppEngine` forwards the inference callback. `engine::build` wraps every engine in `TimeoutEngine`; non-streaming expires the whole request, streaming uses an idle timeout that restarts on every delta (both → `TranslationError::Timeout` / 504).
- Errors: engines return `TranslationError::{InvalidRequest, EngineUnavailable, Timeout, Internal}`; `api` implements `IntoResponse` mapping them to 400/502/504/500 with body `{"error":{"kind","message"}}` (`TranslationError::kind()` is shared with the streaming error event). Empty/whitespace `text` is rejected in the handler with 400.
- API: `GET /health` → `{"status":"ok","service":"translator-core","engine":"<kind>","model":"<model>"}`; `POST /translate` body `{"text","source","target"}` → `{"translation":"[Mock Translation] <text>"}`; `POST /translate/stream` returns SSE events `{"type":"delta","delta":...}` … then a terminal `{"type":"done","translation":...,"elapsed_ms":...}` or `{"type":"error","kind","message"}`.
- Logging uses `tracing` (`RUST_LOG`, default `info`); request logs carry source/target/text_chars/elapsed_ms and error kind but never the raw text.
- Startup warmup is on by default (`TRANSLATOR_WARMUP=false` to disable); warmup failure warns and does not block startup.
- `source`/`target` are accepted but unused by `MockEngine`; `OllamaEngine` builds prompts via `domain::prompt::translation_prompt` (styles: `generic`, `translategemma`, `hymt`) and posts to `{TRANSLATOR_MODEL_URL}/api/generate`, mapping HTTP/connection failures to `EngineUnavailable`. Each style sends its recommended sampling options (`hymt`: 0.7/0.6/20/1.05; others: temperature 0).
- Startup config is env-only: `TRANSLATOR_BIND_ADDR`, `TRANSLATOR_ENGINE` (default `mock`; `ollama` requires `TRANSLATOR_MODEL`, `llama-cpp` requires `TRANSLATOR_MODEL_PATH`), `TRANSLATOR_TIMEOUT_MS` (default `30000`, must be > 0), `TRANSLATOR_MODEL_URL` (default `http://127.0.0.1:11434`), `TRANSLATOR_MODEL`, `TRANSLATOR_MODEL_PATH`, `TRANSLATOR_N_CTX` (default `4096`, must be > 0), `TRANSLATOR_PROMPT_STYLE` (default `generic`), `TRANSLATOR_WARMUP` (`true`/`false`, default `true`), `TRANSLATOR_KEEP_ALIVE` (Ollama keep-alive, default `30m`), `TRANSLATOR_MAX_CHARS` (per-request character cap, default `1500`, over-limit → 400); invalid values abort startup with exit 1. `source` may be `auto` (prompts omit the source language; HY-MT's template is already source-agnostic).

## Conventions

- Commits use conventional prefixes: `feat:`, `docs:` (see `git log`).
- `docs/PROJECT_STATUS.md` and `docs/DEVELOPMENT_LOG.md` are kept as living sprint logs; update them when sprint scope/progress changes, and fix stale statements when touching related code.
- `docs/ARCHITECTURE.md` is the design intent (modularity, model independence, local-first); keep the core crate model-agnostic and platform-independent.
- Releases: use the `release` skill (`.kilo/skills/release/SKILL.md`) — pushing a `v*` tag builds the Windows zip + macOS dmg + Linux deb + browser extension zips and creates the GitHub release.
- Local real-machine verification of the Windows client: use the `local-verify` skill (`.kilo/skills/local-verify/SKILL.md`) — build, stop the installed instance, replace and relaunch it.
- Local real-machine verification of the Linux client: use the `local-verify-linux` skill (`.kilo/skills/local-verify-linux/SKILL.md`) — build with the release version injected, package the deb, install it through pkexec, restart the tray client and hand over for manual checks.
